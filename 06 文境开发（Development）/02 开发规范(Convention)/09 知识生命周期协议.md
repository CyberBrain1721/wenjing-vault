# 知识生命周期协议

---

## 1. 目的

本协议定义文境中知识条目从进入到归档的完整生命周期。

Capture Convention、成卷 Convention、Inbox Standard 各自定义具体操作，本协议定义贯穿始终的状态模型与流转规则。

---

## 2. 状态定义

一条知识条目在生命周期中可处于以下状态：

| 状态 | 含义 | 触发来源 |
|------|------|----------|
| `待发展` | 已收录，尚未进入共创 | Capture Workflow 完成 |
| `共创中` | 正在共创讨论中 | 创作者选择"从藏阁开始共创"并选中此条 |
| `成卷` | 已发展为独立的卷 | 成卷完成 |
| `已归档` | 直接归档（未经成卷）或成卷后归档 | 归藏 Workflow |

---

## 3. 状态流转

```
Capture
  ↓
待发展 ──→ 已归档        （直接归档，未经共创/成卷）
  ↓
共创中
  ↓
已发展成卷 ──→ 已归档    （成卷完成后归档）
  ↓
共创中 ──→ 待发展        （共创未触发成卷，退回）
```

流转规则：

| 从 | 到 | 触发条件 | 执行动作 |
|----|----|----------|----------|
| — | `待发展` | Capture 完成 | 默认初始状态 |
| `待发展` | `共创中` | 创作者选中并开始共创 | 更新 Inbox status |
| `共创中` | `成卷` | 成卷完成 | 更新 Inbox status + 建立双向 References + 保留未选方向 |
| `共创中` | `待发展` | 共创结束但未成卷 | 更新 Inbox status |
| `待发展` | `已归档` | 创作者直接归档 | 移入归藏 |
| `成卷` | `已归档` | 卷终审定稿后归档 | Inbox + 卷均标记归档 |

---

## 4. 各阶段职责

### 4.1 Capture → 待发展

由 Capture Convention 负责：
- Resource Registration
- Payload Acquisition
- Save to Inbox

Inbox Standard 定义输出格式，`status` 字段初始值设为 `待发展`。

### 4.2 待发展 → 共创中

由 Creator Mode 的 Conversation Runtime 负责：
- Agent 更新来源 Inbox 的 `status` 为 `共创中`
- 共创讨论记录保存在 Agent 会话中，不自动写入文件

### 4.3 共创中 → 成卷

由成卷 Convention 负责：
- Step 4.5：更新来源 Inbox 的 `status` 为 `成卷`
- 在来源 Inbox 的 `## References` 中添加指向卷的双向链接
- 在卷的 `创作过程` 文件中记录来源追溯
- **保留未选方向**：共创讨论中未被选择的思考方向，以「待继续思考」形式追加到来源 Inbox 正文末尾，避免有价值的思考随成卷被丢弃

### 4.4 直接归档

由归藏 Workflow 负责（未来实现）：
- 来源 Inbox 的 `status` → `已归档`
- 内容移入归藏目录

---

## 5. 中间产出

共创讨论过程中可能产生新的知识片段（如框架草稿、讨论结论），这些中间产出：

- 以 `【念】` 形式存入 Inbox
- 初始 `status` 为 `共创中`
- 当所关联的卷完成成卷后，这些中间产出的 `status` 同步更新为 `已发展成卷`
- References 双向链接同步建立

---

## 6. 与现有 Convention 的关系

| Convention | 本协议覆盖 | 本协议不覆盖 |
|------------|-----------|-------------|
| Capture Convention | Resource Registration 后的状态赋值 | Pipeline 流程、Resource Policy |
| 成卷 Convention | Step 4.5 来源状态更新、双向链接 | 卷结构、命名、正文模板 |
| Inbox Standard | YAML `status` 字段值域 | 文件命名、YAML 结构、正文章节 |

本协议不替代任何已有 Convention，而是在它们之间建立统一的参照系。

---

## 7. 禁止行为

- 不得跳过状态流转直接更改 Inbox `status`
- 不得在成卷后遗漏来源 Inbox 的状态更新
- 不得在 `## References` 中使用纯文本替代双向链接建立来源追溯
- 不得将中间产出以正文文件形式直接放入卷目录（应以念的形式存入 Inbox）
