# 开发文档生命周期协议

---

## 1. 目的

本协议定义文境开发文档（Convention、Bug、开发日志）的新增、修改与废弃流程。

开发文档本身是文境工程的基础设施。本协议确保开发文档的编号、状态和索引始终可控。

---

## 2. Convention 生命周期

### 2.1 状态

| 状态 | 含义 |
|------|------|
| `Draft` | 起草中，尚未确认 |
| `Accepted` | 已确认通过，当前有效 |
| `Deprecated` | 已废弃，被新规范替代或不再适用 |

### 2.2 流转

```
Draft → Accepted → Deprecated
```

### 2.3 新增规则

1. **编号**：取 `02 开发规范(Convention)/` 下已有文件最大编号 +1
2. **起草**：按 Convention 目录命名规范创建文件，状态标记为 `Draft`
3. **确认**：经 Architecture Review 或创作者确认后，状态 → `Accepted`
4. **索引同步**：新增或状态变更后，立即更新 `00 开发索引.md`
5. **引用**：新增 Convention 必须在正文中声明与已有 Convention 的关系

### 2.4 废弃规则

1. 被新规范替代时，旧规范状态 → `Deprecated`
2. 废弃的 Convention 不删除，保留在目录中
3. 在文件顶部标注废弃原因及替代规范的引用
4. 索引中标记为 `Deprecated` 并注明替代规范

---

## 3. Bug 生命周期

### 3.1 状态

| 状态 | 含义 |
|------|------|
| `Open` | 已记录，尚未处理 |
| `In Progress` | 正在修复中 |
| `Closed` | 已修复并验证 |

### 3.2 流转

```
Open → In Progress → Closed
```

### 3.3 新增规则

1. **编号**：Bug-NNN，取 `04 Bug/` 下已有 Bug 最大编号 +1
2. **模板**：必须包含状态、发现时间、发现方式、问题描述、实际行为、预期行为、原因分析、修复方案
3. **索引同步**：新增或状态变更后，立即更新 `00 开发索引.md`

### 3.4 关闭规则

1. 修复完成后，在 Bug 文件中记录修复日期和修复内容
2. 状态 → `Closed`
3. 索引同步更新

---

## 4. 开发日志

### 4.1 新增规则

1. **命名**：`文境系统开发日志｜YYYY-MM-DD.md`
2. **存放**：`06 开发日志(Journal)/`
3. **索引同步**：新建后立即更新 `00 开发索引.md`

开发日志无状态流转——每篇日志是当日开发过程的不可变记录。

---

## 5. 编号规则总览

| 文档类型 | 格式 | 示例 | 递增方式 |
|----------|------|------|----------|
| Convention | `NN 名称` | `10 开发文档生命周期协议` | 最大 +1 |
| Bug | `Bug-NNN` | `Bug-003` | 最大 +1 |
| 开发日志 | 日期 | `2026-07-01` | 日期驱动 |

禁止跳过编号。禁止手动指定编号（除非修正历史遗留）。

---

## 6. 索引维护

`00 开发索引.md` 是开发文档的统一入口，由本协议与 Current Context Protocol §10 共同维护。

新增、修改状态或废弃任何开发文档后，Agent 必须同步更新索引。未更新索引的 Session 不应结束。

---

## 7. 禁止行为

- 不得跳过编号规则自创序号
- 不得在 Accepted 的 Convention 上直接修改而不经过 Architecture Review
- 不得新增 Bug/Convention 后遗漏索引更新
- 不得删除已废弃的 Convention（应标记 Deprecated 并保留）
