# 一、境·回溯：原生风格基准库

## 背景

Agent 成卷时面对的始终是一个悖论：它需要模仿创作者的语气，但它对创作者文本的唯一接触就是 Vault 内的卷正文——而这些正文本身有一部分就是 Agent 参与生成的。用 AI 参与过的文本去学「创作者原生风格」，是个循环引用。

更根本的问题在于，Agent 目前不方便去自媒体平台上搜索创作者的过往文章。平台反爬、登录墙、内容分散——这些让「Agent 主动收集」这条路成本极高。

## 方案

在 `03 成卷（项目）\` 下建立 `境·回溯\` 目录，由创作者手动放入过往文章。

### 设计原则

| 维度        | 决策                                  |
| --------- | ----------------------------------- |
| **谁放**    | 创作者手动放入，不由 Agent 收集                 |
| **放什么**   | 创作者独立完成的过往文字（非 AI 协作产物）             |
| **目的**    | ① 成卷时方便 Agent 调取素材；② Agent 提取原生风格基准 |
| **提取物去向** | 风格指南存至 `典阁/Library/创作体系/风格指南/`      |
| **不做什么**  | 不爬取平台、不主动搜索、不要求创作者登录                |
|           |                                     |

### Agent 工作流

Agent 在读取境·回溯中的每篇文档时，需完成两项操作：

1. **全文阅读** — 建立对创作者原生风格的理解，不做摘要、不做改写
2. **关键字标注** — 提取文档中的核心概念、人物、事件、地名，创建指向 Vault 内已有笔记的双向链接（`[[wikilink]]`）

关键字标注的目的不是归档，而是将回溯中的素材接入文境知识网络。被链接的 Inbox、成卷或归藏笔记应同步更新其 `## References`，建立双向关联。

# 二、境·发布日志：修改偏好学习通道

## 背景

成卷发布前常有多轮修改。修改中藏着创作者的选择偏好——哪些段落删了、哪些语气调了、结尾从硬改为软——这些微调是 Agent 理解创作者审美的关键信号。

如果只看最终发布版，Agent 学不到「为什么是这个版本」。

## 方案

在 `03 成卷（项目）\` 下建立 `境·发布日志\` 目录，存放修改后的发布版本。

Agent 成卷前，应对比回溯中的原生风格基准 + 发布日志中的修改样本，校准当前输出。

# 五、今日总结

今天的工作量不大，但结构意义清楚。

境·回溯解决的是「Agent 从哪里学创作者风格」的问题。这是一个被绕过的前提——之前的成卷流程默认 Agent 已经理解了创作者语气，但实际上它只有 Vault 内的卷正文作为样本，而那些正文本身就有 Agent 参与。

境·发布日志解决的是「Agent 怎么理解修改偏好」的问题。发布版和初稿之间的差异，是创作者审美的直接信号。没有这个通道，Agent 的修改建议就只能靠通用语感，而非创作者的特定偏好。

两个目录的定位很明确：不是增加流程复杂度，而是减少后续成卷中的风格校准成本。
